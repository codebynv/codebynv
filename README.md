## How I work

- **Understand the problem before coding.** Read the existing implementation and define a small, testable outcome.
- **Prefer correctness over volume.** A meaningful change with evidence is better than activity for its own sake.
- **Keep claims verifiable.** Separate deployed functionality, prototypes, planned features, and known limitations.
- **Use AI as a tool, not an authority.** Review generated code, run checks, and be ready to explain technical decisions.
